# Audit of games/bsb_game.py against Bergault and Sanchez-Betancourt, arXiv 2401.05257

Repository: /Users/bhusain/Desktop/Bilal Saleh Husain/Academics and Research/Repos/partial-info-games (not modified).
Files: games/bsb_game.py (121 lines), src/npg.py (not used by bsb_game.py), notes/overnight_report.md section 2.
Check script and raw output: scratchpad/audit/bsb_check.py (gentle parameters, N = 100) and bsb_check_paper.py (paper parameters, N = 1000).

Overall verdict: the implementation is correct. The brackets are the paper's Theorems 3.4 and 3.7 term by term, the eleven ODEs are transcribed correctly with the right terminal conditions, there is no lookahead and no private-signal leak. The problems are in how the results are read: the "average flow" error reported is dominated by an irreducible finite-population floor that scales as 0.48/sqrt(M_POP), and the report's claim that the ODE values were "verified against the paper's quoted values" is overstated (the paper quotes no numbers).

## 0. Preliminary: bsb_game.py does not use src/npg.py

bsb_game.py is a standalone script with its own `Nets` (two MLPs, line 68-71), `rollout` (73-81), `brackets` (83-89) and `fit` (91-98). There is no GRU, no obs_seq/obs_inc/obs_now, no Solver. Both policies are Markov in current observables. README.md line 10 says "Standalone", but overnight_report.md section 1 ("Each player's policy is a GRU") and section 5 ("Three games now solved by the same code path") do not hold for this game. Not a correctness issue, a reporting one.

## 1. Model and information sets. Verdict: correct (mean-field version), with one caveat

Paper, Section 3.1: dα = -k_α α dt + σ_α dW^α, dα^I = -k_I α^I dt + σ_I dW^I, α_0 = α^I_0 = 0. Code `simulate` lines 49-54: Euler for both, zero initial values. Match.

Paper, Section 3.2: Q^I_t = ∫ ν^I, Q̄^B_t = ∫ (ν^B - ν̄). Code `rollout` line 80: `Qi += nui DT`, `Qb += nubar DT`, `QB += (nuB - nubar) DT` with `nubar = nui.mean(1)` over the M_POP traders on the same path. Match, with ν̄_t = E[ν^I_t | F^α_t] replaced by the population mean (see item 3 for the cost of that).

Price and permanent impact: the paper reduces both objectives to (3.1) and (3.2), in which S and σ_S no longer appear; the impact b ν^B enters as the drift term Q^I (b ν^B + α^I + α) and Q̄^B (b ν^B + α). The code works directly with the reduced objectives, so the absence of S in the code is correct.

Single type: the code sets a_I = ā, φ_I = φ̄ (line 25) and one (k_I, σ_I). Consistent with the paper's "k_I = k_α, σ_I = 0.5 σ_α" numerics (Section 4).

Information. Paper, mean-field model (Section 3.2): both controls are F-progressively measurable where F is generated by (k_I, σ_I, a_I, φ_I, W^α, W^I), so formally the broker is allowed to see the representative trader's private signal. In equilibrium (3.12), (3.17) the broker's control is a function of (α, Q̄, Q̄^B) and the trader's of (α, α^I, Q̄, Q^I, Q̄^B). Code inputs: trader `(t, al, alI, Qi, Qb, QB)` (line 70), broker `(t, al, Qb, QB)` (line 71). These are exactly the state variables of the closed form, so the policy classes contain the equilibrium, and since the broker's bracket is F^α-measurable at equilibrium, E[bracket_B | F_t] = E[bracket_B | F^α_t]: conditioning on the smaller set loses nothing.

Caveat: this is the mean-field information set, not the finite-player one. In the paper's N-player model (Section 2.1) trader n's filtration is generated by (S, α, α^n, Q^n, ν^B); she sees the broker's speed but not Q̄ or Q̄^B. In the mean-field limit Q̄ and Q̄^B are F^α-adapted, so giving them to the trader is legitimate there. In the code's finite population they are population averages and carry O(1/sqrt(M_POP)) of the other traders' private information. This is the finite-population approximation, not a leak of any individual private signal (item 4).

## 2. First-order conditions. Verdict: correct

Paper, Theorem 3.4 (trader): 2η_I ν^I_t = E[-2a_I Q^I_T + ∫_t^T (b ν^B_u + α^I_u + α_u - 2φ_I Q^I_u) du | F_t].
Code lines 85-86: `gI = B_ nuB + alI + al - 2 PHI_I Qi` (times k = 0..N-1), `tI = (-2 A_I Qi_T + rc(gI)) / (2 ETA_I)`, `rc(x)[k] = Σ_{j>=k} x_j DT`. Match.

Paper, Theorem 3.7 (broker): 2η_B ν^B_t = E[(b - 2a_B) Q̄^B_T + ∫_t^T (b ν̄_u + α_u - 2φ_B Q̄^B_u) du | F_t].
Code lines 87-88: `gB = B_ nubar + al - 2 PHI_B QB`, `tB = ((B_ - 2 A_B) QB_T + rc(gB)) / (2 ETA_B)`. Match. Note the integrand carries b ν̄ (population mean), not b ν^B; the code has this right.

Own derivation of the direct control-times-state terms (the term that was missing in another game in this repo):
- Trader, objective (3.1): the only term where ν^I multiplies the state is -2a_I Q^I ν^I, and ∫_0^T 2a_I Q ν dt = a_I Q_T^2, so its Gâteaux derivative is -2a_I Q^I_T ∫ w dt. That is the terminal term already in the bracket. No additional own-impact term exists for the trader.
- Broker, objective (3.2): the term b Q̄^B ν^B is a genuine own-impact term. Its derivative in direction w is b ∫ Q̃ ν^B dt + b ∫ Q̄^B w dt with Q̃ = ∫ w. Integrating by parts with dQ̄^B = (ν^B - ν̄) dt, ∫ Q̄^B w dt = Q̄^B_T Q̃_T - ∫ Q̃ (ν^B - ν̄) dt, so the sum equals b Q̄^B_T Q̃_T + b ∫ Q̃ ν̄ dt = ∫ w_t [b Q̄^B_T + b ∫_t^T ν̄_u du] dt. Combined with -2a_B Q̄^B (ν^B - ν̄), which gives -2a_B Q̄^B_T ∫ w dt, this yields exactly (b - 2a_B) Q̄^B_T + ∫_t^T b ν̄_u du: the paper's (3.5) and the code's `tB`. The own-impact term is accounted for; it is what turns b ν^B into b ν̄ in the integrand and adds b Q̄^B_T at T.

Discretisation convention. The code sums over j >= k (left Riemann including the current step). The exact first-order condition of the Euler-discretised game sums over j > k (Q_k does not depend on ν_k). Both are O(DT) from the continuous-time object. Measured by the exact coefficient-space Picard fixed point (bsb_check.py, part A; gentle parameters, N = 100): rel L2 of the controls at the discrete fixed point against the continuous ODE reference on the same paths is broker 0.49%, average flow 0.80%, trader 0.82% for the code's convention (j >= k), and 2.5%, 2.4%, 2.3% for j > k. At paper parameters with N = 1000: 0.12%-0.16% (j >= k) and 0.6% (j > k). The code's convention is the better of the two and its bias is far below the reported 3-7% errors. Terminal terms use Q at index N (line 86, 88): correct.

## 3. Reference. Verdict: ODEs correct; comparison metric partly confounded

ODE transcription, checked term by term against the paper's six mean-field ODEs (page 13, "the system of equations becomes"), the linear system (3.11), and the trader system (3.18)-(3.22):
- `rhs` line 28-29 (g^b, h^b, g^c, h^c): all four right-hand sides and the terminal values g^b_T = -ā/η_I, h^b_T = 0, g^c_T = 0, h^c_T = -(2a_B - b)/(2η_B) (line 30) match.
- `rhs2` line 37 (g^a, h^a) with g^a_T = h^a_T = 0 (line 38): matches (3.11).
- `rhs3` lines 42-44 (f^a, f^{a,I}, f^b, f^{b,I}, f^c) with terminal (0, 0, 0, -a_I/η_I, 0) (line 45): matches (3.18)-(3.22).
- Ansatz signs: `reference_paths` line 60-61 implements ν̄ = g^a α + g^b Q̄ + g^c Q̄^B, ν^B = h^a α + h^b Q̄ + h^c Q̄^B, ν^I = f^a α + f^{a,I} α^I + f^b Q̄ + f^{b,I} Q^I + f^c Q̄^B, as in the paper's ansatz and (3.17).
- Consistency identities f^a = g^a, f^c = g^c, f^b + f^{b,I} = g^b (from ν̄ = E[ν^I | F^α], E[α^I | F^α] = 0, E[Q^I | F^α] = Q̄) hold to 2e-6 at gentle parameters. At paper parameters they hold only to 1% (|f^a - g^a| up to 0.64 on values of 63) because of the stiff tail (g^b -> -1000 at T) and cubic interpolation of the first solve into the second.
- Parameter assumptions (2a_B - b >= 0, b <= 2η_B, 2η_I, 4φ_B, 4φ̄) hold for both sets.

The report's "matches the paper's quoted values (ga(0) = 63.2, hb(0.95) = -19.4)": the paper prints no numerical values of g, h, f. Figures 2-3 show only t in [0.95, 1] (axes: g^a, h^a in [0, 10]; h^b in [-200, 0]; g^b in [-1000, 0]). The code gives g^a(0.95) = 11.7, h^b(0.95) = -19.4, g^b(1) = -1000, h^c(1) = -833, all consistent with the figure ranges, and g^a(0) = 63.2 appears nowhere in the paper. So the ODE solver is consistent with the paper's figures to the eye, not "verified against quoted values". The term-by-term check above is the actual verification.

Continuous-time reference on a dt grid: yes, the reference is the continuous ODE solution evaluated at the grid points and rolled forward by Euler. From part A above the resulting bias is 0.5-0.8% at N = 100 (gentle) and 0.1-0.2% at N = 1000 (paper). This pitfall is real but harmless here, unlike the Firoozi-Caines case in the report.

Finite-population bias (bsb_check.py, part B): the closed-form linear policies run on a population of M_POP traders, compared with the α-only reference exactly as the code's metric does (`reference_paths` builds Q̄, Q̄^B from α alone, line 60-62; the learned controls are evaluated on population states, line 114). Rel L2 floor:

| M_POP | broker | average flow | trader_i |
|---|---|---|---|
| 32 | 1.3% | 8.5% | 0.02% |
| 64 | 0.9% | 6.1% | 0.02% |
| 128 | 0.7% | 4.3% | 0.01% |
| 512 | 0.3% | 2.1% | 0.01% |
| 2048 | 0.2% | 1.1% | 0.00% |

The average-flow floor is 0.48/sqrt(M_POP) (0.085 x sqrt(32) = 0.48, 0.061 x 8 = 0.49, 0.043 x 11.3 = 0.49): the 1/sqrt(population) scaling is right, and the constant is large because the metric compares the population mean of ν^I (which keeps the averaged idiosyncratic f^{a,I} α^i components) with the F^α-conditional mean. Consequences for the reported numbers: run bsb_a (pop 32) average flow 12.4% against a floor of 8.5%; bsb_c (pop 64) 6.7% against 6.1%; results/bsb_gentle_pop128.log 4.9-5.4% against 4.3%. The "average flow" column therefore measures mostly the population approximation, not the solver. The broker and trader columns (floors 0.7-1.3% and 0.02%) do measure learning error: 3.9% and 3.1-3.7% at pop 128. The report's sentence "Remaining ~5% is a mix of fit noise and the finite-population approximation" should be split that way.

Is there an additional bias from ignoring a trader's own 1/M_POP effect on ν̄? No, under the open-loop concept (item 5): the trader's objective (3.1) does not contain Q̄ or Q̄^B, and ν^B is held fixed as a process in the Gâteaux derivative, so the finite-population open-loop first-order condition of the trader is identical to the mean-field one; for the broker, (2.2) with the ν^n held fixed gives the mean-field bracket with ν̄ replaced by the population mean, which is what the code uses. The only finite-population effect is the one tabulated above.

Paper-parameter run: results/bsb_paper_N1000.log diverges (rel L2 above 100 at iterations 16-18). The coefficient-space Picard map with ρ = 0.5 converges in 34 iterations at those parameters from the ODE initial guess (bsb_check_paper.py), so the divergence is a regression-conditioning problem (brackets scaled by 1/(2η_I) = 500, g^b of order 1000 near T, `SC = 1/100` on line 67), not an intrinsic failure of the Picard map. The report lists these parameters as "untested"; "tested and diverged" is the accurate statement.

## 4. Information and lookahead. Verdict: correct

`rollout` line 78-80: at step k the broker reads `al[:, k], Qb[:, k], QB[:, k]`, the traders read `al[:, k], alI[:, :, k], Qi[:, :, k], Qb[:, k], QB[:, k]`; states at k+1 are written after the controls at k. No lookahead. `fit` line 95 regresses on `al[i, :-1], alI[i, j, :-1], Qi[i, j, :-1], Qb[i, :-1], QB[i, :-1]` with `tt = tg[:-1]`: the same information as in the rollout, indices 0..N-1. Targets `tI[i, j]`, `tB[i]` contain future information by design (they are projected by the regression).

Private signals: trader j's inputs contain only `alI[i, j]` and `Qi[i, j]`; other traders' signals enter only through the population averages `Qb`, `QB` (and through `nuB`, which depends on them). No individual private signal of another trader reaches a trader's inputs. One shared trader network (`s.trd`) fitted on random (path, trader) pairs (line 94-95) is the representative-agent treatment of a single type; correct.

## 5. Equilibrium concept. Verdict: correct (open-loop, matches the paper)

The paper characterises the equilibrium by Gâteaux derivatives with the other player's control and the flow μ held fixed as processes (Lemmas 3.3, 3.6): an open-loop Nash equilibrium in the sense of Casgrain and Jaimungal. The code evaluates each bracket with the other players' realised controls on the same path and regresses on own information (lines 85-88, 112-113): the same open-loop fixed point. The mean field is computed from the population on the same path (`nubar = nui.mean(1)`, line 80) and the same `nubar` enters the broker's bracket (line 87) and the state Q̄^B: Definition 3.1 (iii) at the population level. The broker's bracket correctly uses ν̄ rather than ν^B in the integrand.

## 6. Other observations

- Line 96: `float(loss)` on a tensor with grad (the warning in the logs); harmless.
- A new Adam optimiser each iteration with warm-started networks (line 92); standard for this repo.
- The trader's bracket uses `nuB` (the broker's realised control); if one later restricts the trader to the finite-player information set (ν^B observed, Q̄ and Q̄^B not), the inputs on line 70 would need ν^B and a memory, since Q̄ is then only a functional of the α path.
- The regression projects onto current Markov features. Under the finite population the reduced state is not exactly Markov for E[bracket | F^i_t] (other traders' idiosyncratic states persist and move future Q̄), an O(1/sqrt(M_POP)) effect that vanishes with the floor above.
- Recommended fix for the metric: evaluate the closed-form linear policies on the same population rollouts (as bsb_check.py part B does) and report the error against that, or report the floor next to each number. With that, average-flow error at pop 128 is about sqrt(0.05^2 - 0.043^2) = 2.5%.

## Severity

- No correctness defect found in dynamics, brackets, ODEs, indexing or equilibrium concept.
- Medium (interpretation): the "average flow" error column is dominated by the 0.48/sqrt(M_POP) population floor; the report attributes it partly to fit noise.
- Low (reporting): "verified against the paper's quoted values" overstates the check; the paper quotes no values. "Untested at paper parameters" should read "diverged at paper parameters". Report section 1/5 describe a GRU engine that this game does not use.
